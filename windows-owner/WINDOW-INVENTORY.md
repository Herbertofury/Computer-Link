# Explicit local window inventory draft

Private Windows-native read-only capability: separate Yes consent before enumerating visible top-level captions/PIDs/handles; local preview before any sharing. It excludes child-control text, screenshots, input, process access, admin, network, and application commands. Existing selected-snapshot grant and actual connected-client approval are still separate and required for transmission. Captions can contain private document/chat names, expressly warned before capture. No output is logged or persisted.

Bounded to32 rows,4096UTF8 bytes,256UTF16 title buffer and4096 enumerated windows; limit/truncation/invalidUTF16 refuses whole capture rather than quietly misrepresenting completeness. Control/bidi characters replaced for display. Empty captions are allowed observations, not a claim successfully read protected text. Window handles/PIDs/titles are unverified mutable observations, never future control authority.

Synthetic test creates only own temporary visible/hidden Win32 windows and filters to test PID; checks visibility, close disappearance and oversized-title refusal. Windows-target compile passed, no actual new Windows test yet. No full GUI-consent→inventory→paired-client acceptance yet, no inaccessible/secure desktop or all-browser UIA guarantee, no remote/dot connection. No failed file-dialog test retries.

Existing diagnostic workflow must not silently ship this new runtime before exact scope/privacy/security review. No installer/readiness claim. Official APIs: https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-enumwindows and https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getwindowtextw .

Review correction: capture consent pins session generation after initial stop. Nested Disconnect/Exit/new grant invalidates late Yes before enumeration and before installing captured bytes. Synthetic closure regression proves stale generation does not call the read callback; this is not actual nested-modal Windows acceptance. Added exact32/33row and4096byte/refusal assertions. Pre-capture text explicitly names window handles. EnumWindows covers desktop-app windows, not all modern apps; empty title can mean unavailable or empty, not verified blank. Same-process GetWindowText can synchronously dispatch and stall; no hard deadline/preemptive responsiveness guarantee.

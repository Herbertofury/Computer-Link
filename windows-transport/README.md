# Experimental Windows local transport, not released

Library-only named-pipe implementation; no default listener, CLI, installation, remote endpoint or browser registration. One local fixed-size status/revoke request, no filesystem/desktop capabilities. Explicit protected DACL grants current user only (not logon-session isolation), PIPE_REJECT_REMOTE_CLIENTS, first-instance uniqueness, random BCrypt name and 256-bit in-memory bearer. Pairing() is an internal handoff, NOT authenticated human consent/UI. Same-user hostile process protection and audited constant-time comparison are not established.

Overlapped connect/read/write wait on completion OR owner-stop event with a monotonic session deadline, max60seconds. Cancellation is requested then drained for1second before freeing buffers. If not terminal, heap-owned buffer/OVERLAPPED/event/pipe are intentionally retained and uncertainty returned; this is NOT confirmed shutdown and requires process termination before restart. No workers are spawned. Actual tray/job integration absent. Serial one-shot framing admits exactly the first33 bytes, refuses a short read, and closes after one request; it does not support streaming multiplexing or prove trailing-byte refusal. No remote operation/session revival or automatic reconnect.

Authored Windows tests (six): actual local authenticated status, already-buffered request, wrong token, owner exit during pending connect, no-client expiration and peer revoke closes pipe. Not yet Windows-executed. Initial cross-compile check is not runtime or ACL acceptance. Different-user DACL rejection, cancellation during blocked read/write, split-frame delivery, supervisor crash and UI consent remain gates before any capability or general release.

Official APIs consulted: https://learn.microsoft.com/en-us/windows/win32/ipc/named-pipe-security-and-access-rights and https://learn.microsoft.com/en-us/windows/win32/api/ioapiset/nf-ioapiset-cancelioex . CancelIoEx request alone is not completion; buffers must remain alive until terminal status.

Immediate TRUE I/O completion now uses returned byte count directly rather than waiting on an unchanged event; only ERROR_IO_PENDING enters completion waits. Cancellation drain refuses to free ERROR_IO_INCOMPLETE storage. Status success requires exact one-byte write. The60second deadline is enforced by serve_once, not an automatic timer on an idle unserved Server; callers must close/drop unserved sessions. No clean shutdown is claimed after unconfirmed cancellation.
